# Initial coding-agent handoff

This package is a repository-ready design and Backlog.md seed. It was prepared outside the actual GitHub repository. Its tasks are unimplemented and its acceptance boxes are unchecked.

## First request to Codex or Claude Code

Give the coding agent the unpacked package and this instruction, adjusting the package path to its actual location.

```text
Bootstrap the mShogi rewrite using the unpacked mshogi-design-starter-v0.1 package.

Read START-HERE.md, AGENTS.md, docs/design.md, and MSH-1. Inspect the existing jweathers777/mShogi repository, Git status, branches, and worktrees before changing anything. Preserve existing work and legacy history.

Use an isolated rewrite branch/worktree. If rewrite work already exists, reconcile this package with it rather than overwriting it. Import the design and native Backlog.md records, preserve the shared AGENTS.md and CLAUDE.md arrangement, and complete MSH-1 with verification evidence. Routine local commits and a normal push of the dedicated rewrite branch to the existing configured project remote are authorized. Do not change the default branch or force-push.

This session is repository bootstrap only. Record a durable completion summary and report the next dependency-ready tasks. Product implementation begins in a subsequent bounded task session.
```

The bootstrap-only limit makes the first handoff easy to inspect. It is not a standing requirement for a separate approval after every technical plan. After bootstrap, the normal request is:

```text
Follow AGENTS.md and work on the next available Ready task whose dependencies are satisfied. Carry it through implementation, focused verification, independent review where required, and normal integration. Update Backlog.md with evidence and report the result.
```

John may instead name a task or authorize a bounded batch. A fresh session should not need the original ChatGPT conversation.

## Bootstrap procedure

1. Inspect the target repository and ownership. Record the actual remote, legacy reference, current branches, worktrees, and relevant dirty state in MSH-1. The intended remote is the existing mShogi repository, not a newly invented repository.
2. Use a dedicated `rewrite` branch/worktree. Prefer a fresh orphan worktree if no rewrite exists and the installed Git supports that route. Keep the original checkout and branch untouched. If an existing rewrite is present, integrate with it. Do not use reset, clean, or file deletion to manufacture an empty checkout over existing work.
3. Read the package before copying. Import ordinary project documents with comparison/merging where paths already exist. Do not replace an existing agent policy or active design merely because a starter has the same filename.
4. On a fresh rewrite backlog, copy the supplied `backlog/` config, milestone, and task records. They are already generated by the supported CLI. If a backlog exists, preserve its identities and import/reconcile through the CLI, remapping dependencies and document references when necessary. Do not overwrite colliding task IDs.
5. Use the recorded Backlog.md version, or document and verify an intentional upgrade. Keep the installed CLI and the managed agent instruction block compatible.
6. Check the board, task detail, dependency readiness, shared agent instructions, and `backlog doctor`. Confirm that only the bootstrap task is initially executable and that no task is falsely marked complete.
7. Record evidence in MSH-1, review the import proportionately, and commit the baseline. Push the dedicated rewrite branch normally when the configured remote and access are available. Record a genuine access blocker rather than inventing a successful push or asking again for an already authorized normal push.
8. Report the actual branch/commit, verification, and next available tasks. Keep implementation work for the next selected task.

## Board semantics and verification

The native statuses are `To Do`, `Ready`, `In Progress`, `In Review`, and `Done`. `Done` must remain the last configured status. The CLI's `--ready` flag only checks dependencies; use `--status Ready --ready` to select implementation work.

The CLI does not enforce this project's evidence and review requirements when setting Done. Check acceptance and completion items only when their evidence exists. A bootstrap package is not evidence of an implemented chess engine.

The supplied config disables Backlog's automatic commits and remote fetching. Explicit Git commits and normal pushes follow AGENTS.md. Active-branch checking remains enabled to help discover existing task identities. These tool settings do not replace Git ownership checks.
