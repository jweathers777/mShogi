## Main challenge

An inventory of conventional algorithms plus a persuasive account of lost games cannot establish why the engine is weak. Nor does a faster or deeper variant establish better decisions. Each recommendation should identify an observed decision failure, a mechanism that could cause it, a competing explanation, and the cheapest comparison that would change the recommendation. Keep architectural suspicion, observed gameplay, causal evidence, and proposed remedy as separate columns.

The three independent views are useful only if independence survives synthesis: freeze architecture and gameplay reports before exchanging them; the gameplay auditor should receive complete factual games, identities, exact limits, and failure records but no root-cause labels. Document any prior policy/historical context visible in AGENTS.md or design. Do not claim fully blind review when that context was necessarily visible.

## Bounded evidence-first design

1. Inventory existing records before new runs. Preserve failures, draws, wins, and terminated games. Identify absent histories, mixed source revisions, protocol errors, time forfeits, and opponent configurations. These may qualify the evidence without requiring a new tournament.
2. Freeze a small diagnostic panel before looking at current engine answers. Suggested panel: twelve positions, four tactical/forcing, four quiet positional, four endgame; combine independently sourced non-engine-selected positions with complete-history positions selected by a neutral rule from existing games. Include two successes/negative controls, not only losses. Mark which positions have already influenced implementation; keep at least four genuinely fresh positions for confirmation. If twelve cannot be supported, use fewer and narrow the claims.
3. Establish expected outcomes independently: legal forcing lines with best-defense branches; tablebase-supported outcomes where available with rule/history qualifications; human-explained positional alternatives where no exact oracle exists. Label positional judgments as uncertain. A stronger engine's suggested move is evidence to investigate, not truth by authority. For quiet positions permit sets of acceptable moves/outcomes rather than exact move matching.
4. For each test state carry initial position, full move/event prefix when available, castling/en-passant state, halfmove/repetition context, source and stable identity. Mark FEN-only unknown history explicitly; never silently reconstruct it. Replay to verify the supplied state. The continuation must be evaluated from both sides' best practical replies, not merely the played reply.
5. Use the production time-primary configuration as the baseline. Select a small time ladder (e.g. 1/5/15 seconds, with 30 seconds only on unresolved discriminating cases). Record actual elapsed/search CPU where available, threads, build, executable hash, TT state/size, seed, stop reason and cap, root result, score perspective, completed iteration, incomplete-iteration status, PV and counters. Release build; no concurrent load; explicitly cold or warm TT. Use equal conditions and randomized/interleaved order for timing-sensitive comparisons.
6. Spend new compute only to discriminate a live alternative. A few preselected paired ablations or root-child continuation probes are more useful than rerunning every feature combination. Prefer existing diagnostic controls. Do not introduce production changes merely to manufacture an experiment in this diagnostic assignment.

## Falsifiable mechanism tests

| Hypothesis | Discriminating observation/control | What would weaken it |
| --- | --- | --- |
| Execution overhead prevents useful search | Profile representative hard and easy states; compare equivalent work on the same build/path and observe whether extra thinking time improves independent outcomes. Report hot-path fraction, not isolated function latency. | More time/work does not improve relevant decisions; suspected path is a minor total cost. |
| Selectivity removes a necessary defense or quiet resource | Existing conservative-search control on exact same state/history; preserve time-limited and small comparable-depth/effort views. Inspect root alternatives and best-defense continuations. | Conservative search still misvalues the resulting position, or gains appear only from unmatched extra resources. |
| Frontier/horizon causes tactical misvaluation | From chosen and rejected root moves, test independent forcing/quiet reply branches and resolved endpoints; observe whether extension/time changes reverse an independently wrong ordering. | Ordering stays wrong at resolved quiet endpoints or with required consequence fully within searched branches. |
| Evaluation ranks strategically relevant endpoints incorrectly | Independently justified quiet/terminal endpoint comparisons, score decomposition, perspective/symmetry sanity checks; then verify those endpoints actually influence root choice. | Endpoint ranking is sound, while search never reaches or trusts the critical branch. |
| TT/reuse/history context distorts decisions | Cold/warm and repeatability controls; exact same board with valid differing history contexts where relevant; small no-TT control only if already available. | Changes are lawful tie-breaking, negligible, or arise solely from different work budgets. |
| Ordering/search instability wastes useful work | Root-order or reproducible seed perturbations where supported; track result quality and bound/completion behavior across fixed conditions. | Instability occurs only among equivalent moves; outcomes remain sound. |
| Match/protocol/time handling creates apparent weakness | Audit complete factual requests/results, actual elapsed time, legal responses and termination reasons; replay same request through intended path. | Loss mechanisms reproduce under valid comparable requests and confirmed resource use. |

Ablations interact. Turning off a pruning rule can improve one state while making the engine practically worse by spending all its time elsewhere. Conversely, an ablation's time-limit failure does not prove its omitted lines irrelevant. Label small fixed-depth or fixed-work comparisons as mechanism probes; reserve time-primary results for practical utility.

## Interpretations to reject

- Cross-engine nodes or depth as common units of work or strength. Definitions, quiescence, extensions, reductions, and overhead differ.
- Greater node count or nominal completed depth as proof of useful search. Report main-search versus frontier work where counters permit; nodes are implementation-specific.
- A move's presence in the PV as proof its adverse consequence was adequately searched, correctly valued, or supported by an exact bound.
- Incomplete iteration scores, fail-high/low bounds, or different score conventions as interchangeable exact evaluations.
- One tactical success, one lost game, or an engine's published rating as proof of general strength or a numerical Elo estimate for mShogi.
- Repeated time-limited trials as independent positional samples; multiple positions from one game as independent games; correlated paired colors as independent observations for uncertainty.
- Retrospectively chosen failure fixtures as an unbiased estimate of prevalence. They diagnose mechanisms; fresh confirmation assesses transfer.
- A roadmap ordered by implementation convenience, algorithm fashion, or past tickets rather than discriminating evidence.

## Stopping criteria and final deliverable

No new matches by default. All match runs, if needed, share the single task's 15-minute cumulative active-compute allowance including failures/concurrency. Record actual use; diagnostic position runs also need explicit modest wall/process/output bounds even when not matches. Do not silently turn this audit into a statistical strength study.

Stop initial investigation when (a) independent architecture/gameplay reports are frozen, (b) each leading claimed cause has either a discriminating observation or an explicit unresolved alternative, (c) at least two independent positions support any claimed broad mechanism and one negative/fresh control has been checked where feasible, and (d) additional work would not change the next coherent engineering priority. These are adequacy criteria for recommendation, not evidence of engine maturity. If absent evidence prevents them, stop with a narrower finding and proposed follow-up rather than accumulating anecdotes.

The synthesis should rank no more than three coherent engineering priorities and attach: symptom/prevalence in this selected sample; mechanism confidence; supporting and conflicting evidence; practical outcome to improve; a falsifiable acceptance test and fresh holdout; expected interactions/cost; and why competing priorities rank lower. Distinguish demonstrated defect, plausible bottleneck, and untested proposal. Explicitly state whether practical strength improvement remains unmeasured. Preserve all six-game requirements; no learned evaluation, production implementation, cross-game transfer, or substantial tournament is authorized by this diagnostic audit.
