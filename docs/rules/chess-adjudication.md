# Chess adjudication boundary (MSH-17)

`Game` remains the diagnostic/history layer; `Game::automatic_outcome` describes its current snapshot, not proof that the whole path was legal live play. `AdjudicatedGame` is the rules-owned live boundary over that history. Its constructors accept the standard start, imported FEN, or a history whose entire action path is checked against automatic results. It preserves the chosen claim policy without executing it during historical reconstruction. Later search/match adapters must use this live boundary.

`outcome()` returns None for ongoing games even when optional claims are available. Automatic ordering is checkmate, stalemate, proven dead, fivefold, then 150 halfmoves. `available_claims()` and `validate_claim()` provide current and legal intended threefold/fifty claims. Intended validation normalizes the irrelevant fullmove counter so representation overflow cannot turn an otherwise legal claim into an illegal action. An accepted `claim()` freezes a draw without playing the intention; invalid/late/wrong-actor claims are atomic. `policy_claim()` selects a current claim first, then an intended one, in the profile's documented ordering, only for AutoClaim. ExplicitOnly never forces a claim.

Live `apply` refuses actions after conclusion. `undo` is an analysis operation and reverses an accepted claim first (without undoing an unplayed intention), otherwise one complete action and its history. Claim-bearing records round-trip through `record` and `replay_record`; this validates live actions and accepted claims. Other command/clock observations are explicitly unsupported by this layer; MSH-18 handles them through its [match envelope](chess-match-api.md). Diagnostic `GameRecord::replay_history` retains its observation-only contract.

`Position::dead_recognition()` returns ProvenDead only for kings alone, one bishop/knight total, or bishops exclusively on one square color. Other material/blocked positions return Unknown; this is not a proof that mate is possible. MSH-26 supplies opt-in exact dead-position/side-specific reachability, subject to explicit resource uncertainty. Timeout/resignation handling is provided by MSH-18 with explicit unscored uncertainty.

Verification: `cargo test -p mshogi-core --test adjudication --locked` executes MSH-15 profile expectations for current/intended claims (including projected fourth occurrences), automatic results and checkmate precedence, history-origin boundaries, conservative dead recognition, stored policy, accepted-claim replay, atomic rejection and exact event undo. Existing M1 position/perft APIs retain their diagnostic semantics.

MSH-26 adds explicitly configured [full Article 3 reachability](chess-completeness.md) without changing these M2 defaults. Full live games cache exact/unknown analysis and preserve their configuration through schema 2 records.
