# MSH-158 (Chess Decision Corrections): cached threat-extension trial review

Verdict: no technical blocker for the bounded experimental trial in the currently inspected source. This is not production-retention approval; decision evidence and independent regressions remain necessary. No engines/tests/builds or held-out inspection performed by reviewer.

The trace belongs to a near-alpha PV-verification experiment, which must be distinguished from the frozen production predecessor.

The current implementation requires exact native SearchKey, equal main depth and equal remaining extension credits before reading mate_threat. At this site main depth is positive, so q entries cannot qualify; q stores explicitly set false. Activation requires Conventional mode, enabled null diagnostics, remaining credit, non-check and non-synthetic context. Child depth receives the same one-ply addition and consumes the existing bounded credit as a newly detected threat. It does not synthesize a native move, score, claim, or outcome. Null cutoffs remain under the prior nonPV verification conditions.

Sticky semantics are suitably narrow: a compatible cached flag survives a no-probe overwrite at the same depth/credit context, while an entry at another depth/credit does not transfer its evidence. This is a cached selective-search heuristic, not a proof that a mate threat is an invariant board fact. It can originate from a selective null search and remain dependent on that search's frontier. Existing TT depth/credit identity does not encode every selective-search choice; this patch should not be described as complete TT horizon equivalence.

Additional limits: reuse is enabled in both PV and nonPV calls, including allow_null=false verification calls; this preserves evidence without permitting another null probe and should be intentional in tests. Entry selection ranks deepest compatible-key entries before the later depth/credit filter, so a deeper unqualified entry may hide another flagged entry. That is failure to reuse evidence, not invalid reuse. Table-disabled operation cannot preserve this heuristic and need not produce the same selective choices.

Before production retention: require a targeted regression that establishes extension carryover at compatible re-search and rejection across native history/depth/credit boundaries, disabled-null and Exact behavior, plus existing restoration/cancellation checks. Compare flag-only and combined near-alpha-verification behavior when feasible; otherwise identify the combination explicitly and avoid assigning independent benefit to either component without evidence.
