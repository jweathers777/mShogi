# Offline played-root coverage utility

`played_coverage.py` prepares the complete played-root reconciliation required by procedure revision 2. It performs no engine, network or query work. Use the controller Python with `--self-test` and `--validate-inputs` before final closure. These modes produce fixture/schema checks only. Use `--output played-coverage.json.gz` only after cumulative closure; output is created exclusively and remains subject to independent review.

Each played row has its native pair/game/ply, mover, engine, accepted event and exact history hash. Supplied opening moves have their own context-only table. All native decisions must match the 500k screening identities. Played decisions must have one base-ledger row. The presence of matched 5M confirmation jobs and the exact 20M plan determines evidence tiers. Only the two direct-20M Batch 09 expansion roots use the mixed-expansion tier; the prior 19 cell roots and trigger keep their actual budgets. Mixed coverage does not yield a uniform-budget cell rate.

Base schemas are normalized only at the field-name level: `status` or `disposition` is retained verbatim. Early batches use `dispositions-00-04.json` and `evidence-05-09.json`; later batches use the two gameplay ledgers. Closed selected statuses come from `primary-cumulative.json`, with the exact referenced source row and canonical row hash. No new threshold or status inference is made. Flag values retain their original JSON paths. Screening-only rows remain unresolved. Same-choice and subthreshold labels do not become universal confirmed non-errors.

Input files have exact stored and expanded hashes, including lossless gzip sources. Native reports and compact screening records are checked; existing query-receipt audits are reused without another complete query-artifact hash pass. Final execution requires 200 native games, all ten reviewed batches and zero missing comparisons, then exact native/cumulative totals and exact selected-plan coverage. It records implementation and imported helper hashes. Current schema validation can run before the final batch overlay exists; that mode cannot write a final coverage result.

The utility does not code behavior, infer mechanisms, rank weaknesses or replace final independent statistical and scientific review. Source flags and complete source ledgers remain authoritative; absent normalized secondary tags do not clear earlier uncertainty.
