# Public Chess benchmark source research

Research date: 2026-11-10. No native engine runs, no candidate inspection, no held-out answers transmitted to implementers.

## Verified sources and cautions

### Lichess

[Official database](https://database.lichess.org/) releases puzzle and evaluation exports under CC0, permitting modification and redistribution. Puzzle CSV includes stable ID, pre-opponent FEN, UCI move sequence, difficulty/rating deviation, popularity, plays, themes, game URL and opening metadata. Apply the first move to obtain the actual question; subsequent moves describe the published solution. Mates in one can have several correct moves. Evaluation JSONL supplies four-field FEN plus depth, knodes and one or more scored UCI principal variations; analyses vary in resources and Stockfish version. Neither export alone supplies full repetition history; evaluation records omit clocks too. The official site explicitly permits bounded partial Zstandard streaming. Raw endpoints are https://database.lichess.org/lichess_db_puzzle.csv.zst and https://database.lichess.org/lichess_db_eval.jsonl.zst . Record download date, final URL, byte cap, row count and SHA256. Retain selected raw rows, not the entire database. Engine evaluation and puzzle preferences are finite opinions unless independently proved. Fetch source game PGN for selected game IDs when available; otherwise label history unknown. Do not call synthesized clocks recovered historical facts.

### Strategic Test Suite

[Original author site](https://sites.google.com/site/strategictestsuite/) still exposes a download landing page but the visible page offers no explicit reusable-data license. [Ferdinand Mosca's distribution](https://github.com/fsmosca/STS-Rating) is MIT-licensed and credits Dann Corbit and Swaminathan. Root STS1-STS15_LAN_v3.epd preserves original points; v4 adds Stockfish 15 multipv-10 analysis at 60 seconds per position on one i7-2600K core; v5 rescales points, v6 filters by a 10cp top-two gap. Do not treat that gap as uniqueness proof or STS-derived ratings as strength measurement. Recommendation: use v3 published preferences and retain multiple scored moves; optionally preserve v4 analysis separately. Freeze exact repository commit and preserve its MIT notice plus original author attribution. Important provenance qualification: the repository-level MIT notice is verified, but original authors' independent license grant was not found in the accessible original landing page. Do not state that original STS is CC0 or that the tool author's license resolves every upstream-rights question. If strict affirmative upstream data permission is required, use IDs/local fetch references and explicitly record STS redistribution uncertainty rather than inventing a license.

### Syzygy

[Ronald de Man's generator and terms](https://github.com/syzygy1/tb) explicitly permit redistribution of generated tables. Its code GPL terms are distinct from generated-data terms. WDL and DTZ have different purposes; DTZ is distance to a zeroing move, not mate, and original tables can round DTZ. Fetch complete per-root legal-move maps from the [Lichess tablebase API](https://github.com/lichess-org/lila-tablebase/blob/main/README.md), using `https://tablebase.lichess.org/standard?fen=<encoded six-field FEN>`. The API reports root category and child-position category for each move, so invert child perspective for parent decisions. It also reports precise DTZ when available. Server code is AGPL; a public endpoint is not proof that its response metadata is CC0. Preserve factual results with Syzygy/Lichess attribution. Treat cursed/blessed/rounded/unknown categories explicitly; simplest initial exact-WDL cohort excludes uncertain categories, castling rights and repetition-sensitive claims. A root map supports all WDL-preserving moves, not only its first entry. It establishes one-step preservation under stated assumptions, not practical conversion ability.

## Proposed manageable construction (method recommendation)

Target 240 roots: 96 puzzles (balanced three rating bands and tactical/defensive themes), 60 STS strategic roots (across themes), 36 diverse evaluation roots (material balance, side, phase, evaluation balance, multiple PVs), 48 exact endgames (pawn, rook and minor-piece families; wins and narrow draws). Keep the earlier eight roots a separate regression collection. Adjust counts if the bounded source sample cannot supply valid independent material; report shortfalls rather than weakening provenance.

Stream up to 16 MiB compressed puzzles and 32 MiB evaluations initially, with at most 64 MiB each after inspecting metadata-only diversity. Cancel after cap, parse only complete rows, tolerate truncated zstd tail as an intentionally partial source. A prefix sample is not uniformly random over the whole database: record this limitation. Deterministic hash-ranked selection within predeclared strata is preferable to choosing interesting engine failures. No full downloads or tablebase generation required. Serial polite API calls with backoff; cache every response and stop/retry later on rate limits.

Split roughly 160 development / 80 held out before native evaluation. Same game ID, puzzle line, transposition, mirrored/color-reversed equivalent, nearby continuation and composed-problem family must stay in one partition. Deduplicate canonical board+side+rights+ep (separate clock/history metadata); additionally connect any root appearing along another's known solution/game segment. For unknown-game evaluation rows, conservative near-position grouping and an explicit residual family-leakage limitation are necessary. Mere different row IDs do not prove independent families. Avoid splitting a single endgame composition into near-identical generated variations. Broad themes/material classes should span partitions; they are strata, not all one family.

Keep held-out fixtures/results isolated from builders until the candidate is frozen. A reviewer/data custodian can freeze hashes, validate legality and source provenance without reporting root answers to implementation agents. At checkpoint, compare frozen predecessor and candidate on exactly the same held-out cases. Once an inspected held-out case guides tuning, promote the entire related family to development and replace it before the next claim; preserve old results, never silently re-label them.

Score tiers separately: exact mate/WDL outcomes; published puzzle/STS preferences; finite multi-PV reference judgments; unresolved alternatives. Freeze rubrics and candidate-agnostic adjudication rules in advance. A move absent from finite reference PVs is unresolved, not automatically bad. Do not collapse mixed tiers into a universal accuracy or Elo. Count improvements/regressions/unchanged/unresolved by domain and tier, with meaningful continuation inspections. Five seconds primary; one second secondary; fifteen seconds only on predeclared diagnostic samples. A 240-root five-second predecessor/candidate pass is about 40 engine-minutes, before one-second or focused searches; this is an explicit bounded coherent-checkpoint workload, not a per-edit test. Coordinate resource authorization interpretation with the parent before running it.
