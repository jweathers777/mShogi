# Independent architecture audit — initial, before experiment review

Source: `d53f344`, primary checkout `/Users/johnweathers/Development/Personal/mShogi`, branch `codex/rewrite`, initially clean. Read-only source inspection; no matches, benchmarks, production changes, or prior diagnostic conclusions read. AGENTS.md, Backlog overview, and design A-01–A-05/A-10 reviewed. This is a falsifiable research proposal, not evidence of measured speed, strength, or a correctness verdict. Paths below are repository-relative; line references describe this revision.

## Overall assessment

The implementation is native Rust and correctly keeps real history/adjudication separate from detached null probes. It already has occupancy bitboards, target-centric capture queries, turn summaries, checked previews, an incremental material/PST accumulator, persistent exact history keys, and ordinary alpha-beta refinements. Therefore “replace a naive board array with bitboards” is not an adequate diagnosis. The more consequential architectural question is whether the search spends work on useful discriminating continuations or repeatedly establishes already-known native facts, and whether its frontier/selectivity/evaluation combination values those continuations coherently.

The highest-priority new architectural candidate is a historical-repetition cost cliff. Next are frontier work versus useful nominal progress, conservative low-material search plus unusually restrictive TT reuse, and native transition/evaluator duplication. None has yet been shown to dominate actual decisions or time.

## A. An unreachable historical repetition can permanently select expensive query paths

**Demonstrated source mechanism.** `chess/game.rs:192` checks whether *any* entry of the complete historical occurrence map has count >=2. Pawn moves/captures do not delete those old entries (`game.rs:223`); they are retained correctly for canonical history and undo. `adjudication.rs:449` uses this global predicate to force complete legal actions and intended-claim enumeration at every turn; `search_access.rs:387` uses it to disable prepared previews. `adjudication.rs:210–270` sorts the legal list and validates every intended threefold candidate; validation at `adjudication.rs:156–168` clones Position, calls public `apply` with full structural validation/Undo snapshots, and rebuilds a repetition identity. Thus a repetition that cannot recur still causes expensive, futile claim validation indefinitely along the actual continuation. Separately the TT key already discards irreversible prefixes (`search_access.rs:492`), and `Game::reversible_prior_identities` knows the same rule (`game.rs:197`).

**Smallest falsifier/experiment.** Replay `g1f3 g8f6 f3g1 f6g8 e2e4`. The repeated start is now unreachable. Compare a short fixed-depth full-history search with the *same final FEN and counters* imported as a fresh root, and a similar nonrepeating history. First assert equal legal actions, no claims and no outcomes, then record claim validations, full node expansions, previews, and elapsed distributions (alternating order, three repetitions). The source predicts fewer/no previews and much more claim validation in the preserved-history arm. Measure exact depth/score/move and nodes before interpreting speed. If no measurable overhead appears, native/eval/frontier work elsewhere dominates; do not tune claims first. This is a safe isolated diagnostic comparison because the irreversible step makes earlier identities unreachable, not a general license to replace live history with FEN.

**Potential remedy if proven.** A rules-owned reversible-segment repeated-identity summary, updated/restored atomically alongside full history; keep all canonical history and exact claim semantics. It should be tested across pawn moves, captures, rights loss, undo, EP, current/intended claims and counter boundaries. A scan of all historical occurrence entries also grows with game length even without a repeated entry, so record old-history length independently.

## B. Native facts are repeatedly reconstructed, with substantial work outside “nodes”

**Demonstrated.** Position is a 64-cell array *plus* two color and six kind bitboards (`mod.rs:177`, `attack_cache.rs:87`). Native legal generation scans candidates and clones/resolves/checks a Position for each (`legal.rs:150`, `action.rs:267`). A chosen action is resolved again in a preview or push (`search_access.rs:400`, `action.rs:288`). The preview saves a second committed resolution, but still computes a child legal witness/outcome before pruning. Expanded nodes may then enumerate all legal moves after a previous existence witness (`search_access.rs:315–359`). Quiet q candidates are projected to classify forcing behavior then pushed/resolved again (`chess_conventional.rs:1492–1510`); captures are separately projected through exchange estimation (`:553`), and again applied if admitted.

Hash updates scan all 64 before/after cells (`search_access.rs:679`); evaluation updates scan all 64 (`chess_conventional_eval.rs:253`); repetition identity packs all 64 (`game.rs:51`). Dynamic evaluation reconstructs a heap-allocated piece/features vector and attack maps each call (`eval.rs:307`, `:412`). Search additionally clones the pre-move Position for EvalState (`conventional.rs:654`, `:665`) while SearchCursor clones it for hashing. Every node's `Value` can allocate/prepend a PV vector (`conventional.rs:372–387`); TT entries clone PVs as well.

**Hypothesis/alternatives.** Duplicated resolution, copying, scanning, and allocations could be a large speed ceiling. Conversely tiny fixed boards may copy cheaply; evaluation or branching may dwarf those costs. An “incremental” rewrite could introduce complexity without useful benefit. `work.visit` counts only main/q calls; exchange recursion, legal witnesses, mate probes, claim validation, and quiet projections are not visits. Therefore visits/second and nominal depth alone are poor cross-configuration cost measures.

**Smallest experiments.** Sample one fixed-work and one equal-time run in each of developed, tactical-queen, low-material, and historical-repetition roots. Attribute CPU to native resolution, legal queries, claim admission, eval, SEE, contact probes, TT/key comparison, allocator and clock polling. Add counters only after a profile identifies ambiguous families; no timers on every primitive initially. Use identical release builds and workload traces. Test one local prototype at a time against exact scores/nodes when semantics are unchanged.

**Permitted architectural alternatives.** An opaque native generated-action/transition token can retain already checked effects and a compact list of changed cells, shared by Game admission, hash and eval updates. A native cursor may own compact reversible deltas while public records preserve complete actions/history; private Undo layout is explicitly not the public contract (design A-03). Rules-owned check/pin/evasion masks could avoid resolving obviously impossible candidates, while all effect semantics stay in core. Existing bitboards can support piece iteration; avoid a second search-owned legality engine. Add native incremental repetition packing and cached pawn-only evaluation if profiles justify them. Safe code first; SIMD/unsafe are not justified by this audit.

## C. TT effectiveness is constrained by both policy and representation

**Demonstrated.** Default 4096 entries, maximum 16384, rebuilt every invocation (`conventional.rs:32`, `:279`). Buckets index a full-position hash that includes raw EP and *both* move counters (`search_access.rs:653`). Bounds require exact current identity, counters, and reversible occurrence multiset; reordered keys may build two HashMaps (`search_access.rs:112–181`). Main cutoff also requires extension-credit equality and adequate depth; PV main nodes cannot take TT cutoffs (`conventional.rs:980–1003`). Q entries are budget-specific, and all recursive q actions are unkeyed (`:1339–1409`, `:1510`), so q TT reuse exists only at keyed q roots. Null descendants are fully uncached. Entries contain persistent history keys and full PV vectors rather than compact move/score records.

**Consequences/hypotheses.** A conventional-looking TT may mostly help repeated identical prefixes/iteration ordering rather than different move-order transpositions. A low hit count can arise from collision capacity, distinct legal future histories, counter differences, credit/depth mismatch, or unkeyed q work. These explanations require different interventions. Bigger table alone cannot cure context incompatibility; looser board-only score reuse would violate accepted semantics. A board-oriented move-hint index is separable from exact bound identity, provided hints are admitted from the native legal list. Currently even hint equality includes counters.

**Smallest experiments.** Existing table sizes 0/4096/16384 on fixed-depth roots, logging *position hits → exact context hits → depth/credit hits → cutoffs*, q eligible vs all q nodes, time in equality/store and retained bytes. Add credit-mismatch counters if necessary. Include reversible and capture-rich trees. If capacity is the issue, a larger bounded experimental table requires a deliberate harness change, not an unreported clamp. If context is the issue, first quantify harmless-hint opportunities with a board-only hint index; retain exact bounds. Cross-request TT reuse would require careful root/configuration identity and bounded lifetime design, not a trivial persistence toggle.

## D. Frontier/search interactions can consume time without deepening useful decisions

**Demonstrated.** Q horizon is 16; checks continue at exhausted capture budget until actual ply128. First two q plies consider every legal quiet move, project it, and admit quiet checks or confirmed queen-contact threats (`conventional.rs:1414–1553`). Threatened turns expand all defences, with an extra reply-mate probe at the boundary. Immediate supported queen-contact mates are probed at every q node. Contact query geometrically restricts queen distance/pattern then performs native candidate and reply validation (`attack.rs:20–103`). It does not identify all tactical threats. The main search also calls contact threat detection when protecting candidate reductions/omissions. These costs are partly hidden from visit counts.

LMR, null and shallow omissions all require sufficient material on *both* sides (`conventional.rs:1574`: >=600 nonpawn cp each); low-material standard search therefore loses all three major reductions, apart from opt-in endgame LMR. Depth1 searches all root moves and full q subtrees, and incomplete iterations provide no replacement choice. PVS, aspiration and reduced-depth re-searches can replay large frontier subtrees. Quiet history is source/destination; continuation history uses only previous and current destinations, pooling unrelated piece/context situations (`:778–785`). Ordering computes SEE for all tactical moves when the hint fails; q ordering does so for all candidates even when the first capture would cut off.

**Competing explanations.** Time spent proving forcing threats may be exactly what prevents catastrophic choices; reducing it can raise depth while lower decision quality. On other roots a broad frontier may duplicate main search and prevent useful quiet planning. Low-material caution avoids zugzwang/reduction errors but may make a simple endgame disproportionately hard. History aliasing may damage ordering, or be insignificant relative to frontier evaluations. No “algorithm is present” claim establishes its practical effectiveness.

**Smallest experiments.** First use existing orthogonal ablations at fixed depth and equal time, reporting chosen-move correctness plus outcome along independently specified continuations. Separate LMR from null from quiet omissions from SEE from delta. `Exact` is not a clean selectivity control: it simultaneously changes the frontier to static leaves and removes extensions. For q specifically, add bounded harness-only controls only after methodology review: keep capture/check-evasion correctness fixed while comparing quiet forcing depth and contact-probe admissions. Measure solve time, stability at increased time, continuation outcome/regret and avoided failures, not just seldepth/q ratio. Analyse iteration incremental work and interrupted-work share.

## E. Evaluation can be transparently computed yet poorly calibrated

**Demonstrated.** Material/PST terms are incremental, but dynamic mobility, king safety, pawn threats and conversion dominate feature construction. Geometry intentionally includes pinned pieces and treats attacked undefended material with small bonuses (`eval.rs:412–663`). Passed-pawn bonuses are quadratic in rank, and king interception alters only an extra runway premium (`:467–509`, `:674`). A specialized ending can replace all generic terms (`:123–139`): KPK uses exact board WDL plus heuristic conversion gradient; other ending recognizers are bounded patterns (`:715–886`). Abrupt transitions into/out of specialized matching or phase/material gates can create preferred positions without a sound continuation. All coefficients are original untrained heuristics, not independently calibrated values.

**Falsifiers.** Inspect static ranks and searched outcomes across matched near-neighbor sets: supported versus hanging passers, blocked versus unblocked, pinned versus truly available attackers, safe versus unsafe major trades, conversion progress versus repetitions. For a failure, force each candidate continuation through native full-history replay and compare the point where static ranking or search bound diverges from the independent tactical/endgame outcome. Disable one evaluation term *with fixed search treatment* only as a diagnostic. Do not use a PV's existence as proof that consequences were seen correctly. KPK exact WDL does not establish fifty-move/claim feasibility or a conversion strategy; those remain search/history questions.

## Harnesses and methodology cautions

- `crates/mshogi-search/examples/chess_frontier_profile.rs` is the best current full-history driver: JSON initial FEN/history, root-FEN assertion, time, depth, table and orthogonal ablations; outputs per-iteration work, PV native replay and eval decomposition. It accepts `tb_moves` for legal-set checks and expected-line replay, which prove admission only. It hardcodes AutoClaim; ExplicitOnly needs a transparent harness extension.
- `chess_cost_profile.rs` supports fixed work/table/depth and bounded timed mode but mostly synthetic FEN-only roots. Useful for overhead isolation, inadequate for real-history diagnosis alone.
- `chess_conventional_profile.rs` emits `soft_ms:700` while actually supplying `TimeBudget::from_hard_ms(1000)` (both budgets1000): lines28/45. Do not copy this metadata as observed configuration. Its20k visit ceiling also prevents it from being a pure equal-time profile.
- `mshogi-core/examples/chess_search_access_profile.rs` compares public versus cached native queries on depth2 walks, but always asks for full `node()` and does not exercise current lazy turn/preview behavior. It cannot establish present search-wide speedup.
- Unit `chess_conventional_eval.rs:1537` contains a bounded ignored eval profile. Existing search/core regression suites supply exact differential, key collision/history/restoration and special-effect checks; preserve these for future prototypes.
- The product engine delegates to conventional search through `coordination.rs:338`; frontend/Python is absent from node execution. Server framing, root load and coordination overhead should be measured separately from native search, especially short budgets; it is not an explanation for costs deep inside q nodes.

Suggested initial screen: approximately eight independent roots spanning the above mechanisms, three alternating fixed-work repetitions and 1s/5s only when needed to separate cost from decision quality. Escalate to15/30s only on discriminating cases after reviewing the first observations. No opponent games needed. Preserve complete histories, compiler/flags/revision, actual wall/CPU use, hard kill bounds and input/output hashes. Stop each hypothesis when its predicted mechanism is absent or when one small intervention distinguishes it; do not turn the screen into a rating study.
