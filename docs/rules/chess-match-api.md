# Match commands, clocks and semantic replay (MSH-18)

`ChessMatch` owns an `AdjudicatedGame`, pending draw offer, injected-time clock, conclusion and totally ordered versioned request/response log. Match commands are distinct from board actions. Every board mutation uses the live rules boundary. No engine, I/O, system clock or evaluation-based resignation/adjudication is built into this layer.

`TimeControl::Untimed` and `Increment { initial_ns: [white, black], increment_ns }` implement the approved software controls. Initial balances must be positive; increment may be zero. `Start` marks the active player's first request boundary, leaving setup/handshake time uncharged. Submit monotonic integer nanoseconds with actor and current event version; every logged observation advances version, even if rejected. Action ply and match version are different identities.

On arrival, preserve prior conclusion, reject decreasing timestamps, charge the active side, and process zero/negative remaining time before the requested operation. Arrival exactly at the deadline flags. A nonterminal accepted move receives one increment and starts its opponent at that timestamp. A terminal move receives no increment. Rejected operations leave the board intact but consume elapsed active time and receive no increment; invalid timestamps leave clock balances intact. Stale requests are rejected after time charging. Increment overflow rejects the move atomically. No sleeping or wall-clock scheduling is needed in tests.

Offers persist until the opponent moves, declines, accepts or the game concludes. The offering player's move preserves the offer; repeated offers cannot withdraw it. Acceptance requires an opponent offer and at least two recorded alternating actions, establishing both players have moved. Imported fullmove counters do not satisfy that condition. Valid claims stop the clock without playing intended moves. The core retains optional claims; the unattended runner must explicitly submit its selected policy claim before requesting another move.

Resignation and flag fall inspect the opponent's mating feasibility. A bare king or globally proven-dead state proves impossibility. A supplied cooperative continuation must consist of legal actions and end in that opponent delivering checkmate. No certificate and no impossibility proof yields `Unresolved`, with no chess score. Invalid evidence never cancels a resignation or postpones an established flag: record the rejected witness and stop explicitly unresolved. Ordinary material advantage or a failed dead recognizer cannot establish a win. Automatic prior outcomes always take precedence. `white_score_twice` returns None for unresolved terminations.

**Hypothetical-path interpretation.** Positive certificates use Article 3 legal-move reachability, not adversarial forced mate or future controller claim policy. Counter values are normalized on private hypothetical positions so storage overflow and 50/75 counters do not alter move geometry. This interpretation follows the Laws' definition of a legal move in 3.10.1 (Articles 3.1–3.9), combined with the any-legal-series conditions of 5.1.2/6.9. It is a documented interpretation, not a new owner policy; current live automatic results still take precedence before any feasibility query. Primary reference: [FIDE 2023](https://handbook.fide.com/chapter/e012023), consulted 2026-10-25. Full possible-mate recognition remains MSH-26; this M2 layer only accepts sound proofs/certificates and otherwise preserves uncertainty.

`MatchRecord` is a strict versioned JSON envelope containing the initial canonical live record as a string (retaining the nested codec's duplicate-field checks), exact control, ordered requests and computed replies. `replay()` rebuilds game/offer/clock/conclusion/rejections from recorded timestamps and refuses mismatching observations. It does not remeasure elapsed time or rerun an engine. Runner engine configuration/process failures belong to MSH-23's envelope, separate from chess outcomes. Protocol watchdog expiry is never a chess flag in this API.

Verification: `cargo test -p mshogi-core --test matchplay --locked` directly executes the independent MSH-15 clock and resignation/flag fixtures, plus offers, stale/invalid requests, overflow, claims, witness handling and corrupted-record rejection. All time tests inject integers; no sleep or performance claim is involved.

MSH-26 adds [opt-in full mating reachability](chess-completeness.md): schema 2 match envelopes preserve configured work limits and generated feasibility evidence. Existing schema 1/M2 behavior remains unchanged. Full-mode budget exhaustion remains explicitly unresolved and unscored.
