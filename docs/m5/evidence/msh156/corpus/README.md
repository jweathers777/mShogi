# MSH-156 (Independent Chess Benchmark): frozen data

This package contains a 240-position benchmark split before candidate measurement into160development/80heldout. The current eight-position set is a separate regression collection. `metadata.json` commits exact execution-file SHA256s. Do not expose heldout rows, answers or per-root results to implementation agents until a candidate and measurement plan are frozen. Any heldout family later used for development must be promoted and independently replaced before another validation claim.

The public fixture files include180licensed/public factual source positions. SixtySTS entries are references only: source IDs/line numbers/hashes and empty state/expectation slots. The mirror's MIT notice is retained, but its original authors' data permission was not established. No STS FEN, answer list or EPD row is redistributed here. These references preserve the frozen selected corpus without implying an upstream license. Do not package future STS result logs containing those positions/answers as freely licensed source data.

To reconstruct exact local execution files, obtain the public v3 file from `https://raw.githubusercontent.com/fsmosca/STS-Rating/master/STS1-STS15_LAN_v3.epd` into an external scratch path. Then run `python reconstruct.py --sts /scratch/STS1-STS15_LAN_v3.epd --out /scratch/msh156-execution`. It checks the original full-source hash, every selected row hash and both final fixture hashes. A changed upstream file fails explicitly. Reconstruction was verified byte-identical for both partitions. The pinned hash is in fetch-manifest.json; preserve a local lawful source cache for long-term reproducibility. Do not substitute a newer version silently.

Execution schema uses `fen` as known history origin, `history` as UCI moves, and `expected_root_fen` with raw en-passant targets. Source rows, original clocks and unknown-history declarations are retained. Source UCI_Chess960 castling is converted to orthodox root moves; raw evaluation PVs retain original notation. Runtime source paths are original provenance; game/TB receipts are also included under relative games/ and tb-raw/. Adapt receipt lookup paths without changing position/history/expectations.
