## 1. Exact obsolete-repetition gate repair

`Game::has_repeated_identity` (`game.rs:193`) scans complete archival occurrence counts. It drives `claims_with_actions` (`adjudication.rs:215/221/250`), `search_needs_claim_actions` (:450), and preview rejection (`search_access.rs:394). The archival map must remain complete, but a repeated identity before a pawn move, capture or castling-right loss cannot affect future claims. Existing `reversible_prior_identities` and SearchKey already use this fact. MSH-154 established 44/605 obsolete-only decisions in 2/12 games, none of the selected twelve roots: exact narrow waste, not general weakness.

Small safe implementation: cache one boolean on Game, meaning that an identity has repeated in the current reversible segment. Save its old value in each private Step for undo. On `commit_after`, compute irreversible using `after.halfmove_clock == 0 || before.castling_rights != after.castling_rights`; set false on irreversible; otherwise retain old flag OR the new identity's occurrence count after insertion >=2. Initial imported/standard state starts false. On undo restore the saved flag. No second occurrence map is needed: an identity in the new reversible segment cannot equal a pre-boundary identity, so the complete map's count for the newly added identity is exact for this test. Preserve full map/actions/origin and public current/intended validation. Rename predicate/comment to communicate reachable/reversible meaning. This does not truncate the public game or search key.

Tests required: repeated knight cycles then pawn move; actual capture; irreversible rights loss without zeroing halfmove; quiet continuation and a new repeated cycle after boundary; pop across each boundary restoring flag and public equality; stale preview and null paths; explicit/current/intended threefold, fivefold, fifty/75 move, imported unknown histories, legal-vs-raw EP, counter overflow rejection atomicity. A slow independent test helper scans actual stored/replayed identities since irreversible events and compares the gate after every step/undo. Assert public claims/outcomes against existing explicit known fixtures, not only old/new internal gate agreement. Positive live-repeat control must continue to prohibit preview/allow exact claim; obsolete-only control should admit preview and preserve catalog and legal results.

Cost check: reuse existing MSH-154 full-history versus reversible-suffix inputs, alternating fixed traversal and 1/5s affected roots. Require equal fixed-depth decisions, scores, visit counts where semantics are unchanged and no affected-state drift. Report original archival history retained. Expect cost cliff removal only in affected paths; do not claim broader strength.

## 2. Checked claim projection reuse, broader than obsolete histories

MSH-154 live-repeat profile: repetition packing 23.8%, structural validation 17.2%, claim-catalog body 9.1% exclusive sampled tops. Claim catalog invokes `validate_claim_without_outcome` once per action per reason. That public validator clones the position, sets fullmove=1 (important unplayed-move representability rule), calls public `apply` returning full before/after Undo, computes repetition identity even for fifty-move-only checks. In dual-threshold positions the same action is projected twice.

Bounded prototype entirely inside native adjudication: retain public validator and its error contract as independent reference; within catalog construct a normalized-fullmove base once, call authoritative `checked_after` once per intended legal action, and reuse resulting halfmove/identity for both candidate reasons. Only pack identity when threefold prerequisite holds; fifty threshold can read after.halfmove. Emit current threefold/fifty first, then all intended threefold sorted, then intended fifty sorted exactly as now. Do not switch to action-order interleaving. Reject/fail projection consistently rather than assuming that a legal list guarantees counter representability. Normalized fullmove=1 must remain: the existing fullmove-u32-max intended-claim tests distinguish this from actual move admission. Do not bypass authoritative resolve/check.

Tests: compare complete ordered catalogs against enumerating public validate_claim over every legal action and both reasons on independent histories at clocks 98/99/100/149/150, live repeat, combinations of repeat+clock, castling, EP, promotions, claimable mate/stalemate/dead precedence, fullmove max. Native search cursor summary/node and full/auto/explicit modes must agree; public invalid intended action errors unchanged. Check the full legal set once, don't derive expected subset only from optimized implementation.

This provides a coherent native-query increment with narrow change scope and potential benefit on necessary live histories. It is not a new representation. Stop if fixed traversal/correctness diverges or representative timing improvement is absent.

## 3. General transition/delta prototype only after first evidence

Existing previews already retain checked child state and summary; `push_preview` validates exact context, and `apply_for_search(prepared)` avoids duplicate resolution. Do not reimplement that optimization. Remaining measured costs include full-board update_position_hash and EvalState::push (~3% each), geometry (~14% tactical), resolve (~10%), apply_resolved (~5%). A compact native changed-cell descriptor from existing Resolved could reduce separate 64-square hash/eval scans, but it expands cross-crate API and special-move tests. Defer until benchmark and profile identify worthwhile total cost; do not assume replacing board representation is needed.

If selected, opaque native token owns authoritative changed squares (ordinary move/capture, castling rook pair, EP victim, promotion) and exact old/new occupants. Search consumes the token, never authors legal effects. Keep safe Rust, exact context/stale-token protection and ordinary fallback. Compare complete position, counters, raw/legal EP, rights, legal actions, identities, outcomes, history and undo on varied trajectories. Fixed-traversal score/work equivalence plus equal-time benchmark non-regression; no speed-only better-Chess claim.
