`msh156-runner.py` adapts the native branch and sequential process supervisor of committed `docs/m5/evidence/msh155/runs/driver.py`; no product code or reference-engine layer is added. Use the existing Python-chess environment. Prepare accepts a root array or object with `roots`; it checks unique IDs, legal supplied histories and expected root FENs, freezes panel/driver/binary SHA256 and source-revision metadata, and performs no searches. Five seconds is the default per-cell allowance. Separate output manifests select different budgets/diagnostics or predecessor/candidate binaries. Do not reuse an output directory.

Verify its frozen build provenance, legal returned action/PV, restored root, deadline telemetry, six requested diagnostic flags, UTC receipts and resource aggregation. Charge smoke to the shared round ledger. If it fails, retain the attempt and investigate; create an explicitly identified retry output only after resolution. This smoke does not inspect held-out answers.

Limits retained honestly: each output lock prevents concurrency inside that run only; coordinator must enforce sequential execution across directories and maintain the overall round budget. Per-run budget is active-search charging on valid success and total process wall on failure, with 15s watchdog reserve. Native-process UTC receipts bracket process startup/reporting as well as search; exact elapsed search time remains native telemetry. A controller crash creates orphan evidence and intentionally blocks resumption rather than guessing unrecorded resource use. Source revision is supplied metadata, not automatic proof that the executable was built from it; preserve build/source attestation separately. No held-out contents were accessed for this adaptation.

Wrong-ID, wrong-time and wrong-diagnostics playback fixtures all fail and charge elapsed wall. All runs in the round must use the same registry path; creating a different registry would be an explicit new budget domain, not authorized automatically. No engine searches were made.
