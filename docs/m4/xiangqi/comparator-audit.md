## Board enumeration candidates

**Pikafish has an actual complete-board enumerator in this pin.** `src/movegen.cpp:140–165` defines `generate<ALL>` as EVASIONS when checked, otherwise legal CAPTURES plus QUIETS. It is not Stockfish chess's `generate<LEGAL>` API. `src/perft.h:32–66` recursively enumerates `MoveList<ALL>`, applies/undoes each move, and emits root divide counts. That path does not call `rule_judge`; perft therefore does not prove history/outcome conformance. The public `Engine::perft` first calls `verify_network` (`src/engine.cpp:122–125`), so the apparent public perft entry point is not a demonstrated network-free harness.

Source mechanisms supporting a future bounded board reference:

- `src/attacks.h:109–117,138–158,164–228,246–258`: forward/lateral pawn geography; cannon hurdle rays; horse leg and elephant eye blockers; elephant half-board restriction; king/advisor palace targets.
- `src/position.cpp:438–444`: king-facing checks include the opposing KING on rook rays. `src/position.h:270–285` extends king threat rays on the same file, used for king-destination safety.
- `src/movegen.cpp:33–54,73–94,109–132`: intersect all current-check blocking/capture targets, treat cannon screens specially, recompute after moving constrained blockers, and reject quiet insertion of a new enemy cannon screen. These are particularly important evasion risks; source presence is not a correctness proof.
- `src/position.cpp:450–501`: separate arbitrary-move legality checks; own side/destination constraints, cannon quiet geometry, king threats, pins and newly created cannon screens. A future admission should cross-check this predicate against the full enumerator on the admitted domain rather than assume equivalence.

**Fairy-Stockfish also has a complete enumerator but needs the correct build and variant.** `src/variant.cpp:1248` places full-size xiangqi under `LARGEBOARDS`; `1731–1751` configures 9×10 xiangqi and `AXF_CHASING`. `src/movegen.cpp:507–525` checks immediate game end, generates EVASIONS/NON_EVASIONS, then filters every candidate through `pos.legal` and excludes virtual drops. `src/search.cpp:121–147` perft uses `MoveList<LEGAL>` with do/undo. Evasion generation includes non-sliding rider special handling (`src/movegen.cpp:384–400`), important for horse blockers and cannon screens.

Its geometry chain is explicit: `src/variant.cpp:1224–1245,1731–1745` selects HORSE, CANNON, SOLDIER, ELEPHANT, diagonal FERS advisor, WAZIR king, palace/river regions, soldier river rank, no castling/double step, facing-general constraint and stalemate loss. `src/piece.cpp:196,217–224` supplies the corresponding move definitions (`mRcpR`, `fsW`, `nN`, `nA`, `W`); `src/position.h:1275–1302,1305–1316` applies side/region constraints and restricts uncrossed soldiers to their file. `src/position.cpp:1264–1284` independently rejects an exposed facing-general ray and checks king destination safety.

The candidates share Stockfish ancestry. Agreement between them is useful evidence, but not two fully independent rules derivations; a shared defect remains possible.

## Protocol, source license and networks

Pikafish's pinned loop supports native **UCI**, including `uci`, `position`, `go`, `stop`, `isready`, `ucinewgame` (`src/uci.cpp:114–146`); searching pinned `src` found no `UCCI`, `ucci` or `RepetitionRule`. Its move coordinates are files a–i/ranks 0–9 (`src/uci.cpp:604–605`); input-move matching uses the complete ALL list (`631–636`). The parent reports current website documentation describing RepetitionRule; that page was not inspected in this source-only audit and is a **different documentation candidate**; it must not be attributed to this source pin or turned into a claimed selectable profile.

Fairy-Stockfish natively recognizes UCI/UCCI/CECP/USI (`src/uci.cpp:346–368`), selects xiangqi for UCCI only in a LARGEBOARDS build (otherwise minixiangqi), and supports UCCI banmoves (`377–383`). Standard UCI initially defaults to chess; explicitly select `UCI_Variant=xiangqi`. Critically, generic UCI coordinates use ranks **1–10**, while full-size UCCI/UCI_CYCLONE/other non-general modes use **0–9** (`src/uci.cpp:474–486`). Pin dialect with coordinate normalization; never send identical unnormalized move strings to both candidates. These are source-supported capabilities, not runtime protocol admission.

Engine code distributions state GPLv3 (`Pikafish README.md:110–126`; Fairy-Stockfish `README.md:110–126`; both `Copying.txt`). Preserve exact source/license/build provenance for any future distributed reference tool or binary. The report makes no legal interpretation of distribution obligations.

Networks are separate artifacts, not identified by these engine commits. Pikafish `src/evaluate.h:32–36` names `pikafish.nnue`; `scripts/net.sh:8–24` downloads that mutable filename from `master-net` and merely skips an existing file. `src/Makefile:1092–1095,1218–1219,1230` invokes the network step for normal builds/config sanity. `README.md:130–131` separately attributes Pika Xiangqi Zero training data under ODbL; that is not a checksum or a license declaration for a particular weight file. Fairy-Stockfish `README.md:20–21` points to optional external networks/dedicated releases; `src/ucioption.cpp:203–207` and `src/Makefile:346–348` expose disabling NNUE/embedding. Future opponent admission must record exact weight URL, SHA-256, size, provenance, applicable license and engine compatibility separately. No weight license, availability, strength or reproducible binary is established here.

## Proposed future bounded reference and sentinels

Do not build an adapter during MSH-80. For a later separately scoped admission, expose only: validated board+side input, normalized 0–9 complete move set, in-check status, one-move apply/undo board round-trip, and shallow perft/divide under a declared board-only convention. Prefer a small source harness if public perft forces NNUE; retain and review its exact patch. Independent expected cases must be fixed before differential execution.

The following are rule-derived proposed sentinels, **not executed successes**. Coordinates mean red at the bottom, a0–i9. WXF2018 movement basis: official English PDF article 1.4 setup; articles 2.1–2.10 (PDF pages 11–13, printed pp.3–5). Local OCR was consulted only as a reading aid; visually confirm diagrams/clause wording when admitting final fixtures. Kings remain on board; use an independent domain validator and safe background placement to avoid unrelated checks.

| Horse leg and elephant eye | A horse on e4 with a piece on e5 cannot reach d6/f6; removing e5 restores those destinations absent other restrictions.
