## Current architecture findings — source PASS

- `desktop/src/main.tsx` normal startup mounts only ProductApp. ProductApp invokes exactly one `useGameSession`; game changes replace a keyed ApplicationView inside the same owner. There is no alternate Chess App or useNativeSession.
- `product/useGameSession.ts` owns one current snapshot/ref, one serial operation gate and busy/error state, one close listener, and one recursively scheduled snapshot poll. StrictMode cleanup retires old poll/listener callbacks. Native receipt acceptance compares monotonically increasing document/revision. Commands carry the exact rendered token, files the exact Open token. A late Save returns the newer native snapshot if polling has already accepted it, never an older clean receipt over newer dirty work; replaced-document receipts return null. Native host remains authoritative.
- `product/ApplicationView.tsx` owns one ApplicationShell composition and shared sections/dialog/recovery lifecycle. Analysis, Game Actions, Moves ordering is structurally identical, not three game pages. Shared header owns New game/Save/Load and document title/state. GameFrame supplies common upper-player/board/lower-player/footer slots. GameCapabilities composes native-specific claim/declaration/terminal controls without another app owner.
- `interaction/useNativeChoiceController.ts` is the one board selection/prefix/completion/inspection/generation/focus lifetime. Chess/synthetic Board, ShogiBoard, and XiangqiBoard call it. Renderers provide ordered keys and geometry only. `useMovementInspection` is a stateless query/identity validator; it has no competing mounted/generation/selection ownership.
- Complete choices remain opaque native actions. Prefixes preserve ordered routes and same-endpoint alternatives. A partial route never submits. Complete-versus-continue requires explicit choice. Complete alternatives use the native completion IDs, synchronous duplicate latch, current context/state identity and exact supplied-choice membership. Occupied legal capture/inspection priority is common. Inspection cannot submit an action; query supersession, cancel, capability/orientation/identity change and unmount retire old handlers.
- Shogi retains native promotion state, ownership/rotated kanji pieces and hands. Xiangqi retains actual native intersection geometry, river and palace diagonals plus Red/Black artwork; frontend does not derive movement or adjudication. Chess retains its specialized square/promotion renderer. NativeBoard remains a stateless generic rendering adapter plus shared DTO/newness utility; R5 explicitly retained it. It has no second controller and is not an obsolete IPC facade.
- `verification/bootstrap.tsx` routes nonsynthetic verification modes to the actual ProductApp. The explicitly labeled synthetic app supplies the same Board/controller and distinct native fixture commands/records; its separate QA-only owner is not a hidden normal product application.
